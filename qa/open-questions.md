# Open Questions

Items found while reading the code where the intended behaviour is unclear. Test cases touching these points should be marked **Blocked** (or executed against current behaviour and flagged) until answered.

| ID | Area | Observation in code | Question | Affects |
|---|---|---|---|---|
| Q-01 | Order status | `POST /api/Orders/{id}/pack` requires status `Picking`, all pick tasks `Completed` and every container at a `DockDoor` location. But the last dispatch (`PickTaskService.DispatchContainerAsync`) already sets the order to `Packed`/`ShortShipped`, and dispatch moves the container to a conveyor location, not a dock door. | Is `/pack` still part of the intended flow? Under what conditions should it return 200? | TC-26, API-37 |
| Q-02 | Order status | `OrderStatus.Shipped` and `OrderStatus.Canceled` exist, but no endpoint sets them. | Are shipping and order cancellation out of scope for this release? | Order status tests |
| Q-03 | Order status | An order parked as `AwaitingReplenishment` cannot be allocated again (`AllocateOrderAsync` requires `New`). | How should a parked order resume once stock is replenished? | TC-22, TC-26 |
| Q-04 | Access control | `POST /api/Orders` has only class-level `[Authorize]`, so Worker, Brigadier, Admin and Integration can all create orders. | Is it intended that Workers can create customer orders? | TC-05 (DT-1) |
| Q-05 | Validation | `POST /api/Orders` validates only `requiredQuantity > 0`. Empty `items`, empty `customerName`/`destinationAddress` and a non-existent `productId` are not checked. | What is the expected response for each of these inputs? | TC-29; raised as BUG-02, BUG-03 |
| Q-06 | Validation | `POST /api/Products`, `POST /api/Containers` and `POST /api/Locations` have no duplicate or required-field checks (unlike `POST /api/Inventory/products`, which returns 409 for a duplicate SKU). | What status code is expected for a duplicate SKU / container barcode / location barcode on these endpoints? | API-71, API-74 |
| Q-07 | Goods receipt | `POST /api/Stocks` does not check that `productId` exists and, unlike putaway/relocation/adjust-stock, writes no stock transaction (audit) record. | Is this endpoint still used, and should it be audited and validated? | TC-10 |
| Q-08 | Picking | Dispatch looks up `conveyorBarcode` by barcode only; the location type is not checked, so any existing location (e.g. a shelf) is accepted as the conveyor. | Should dispatch reject locations that are not of type `ConveyorDrop`? | TC-21; raised as BUG-04 |
| Q-09 | Access control / UI | The terminal has no role-based UI: every logged-in user sees "Admin: Inventory", and the API allows Worker to call `adjust-stock` and create products (`AnyStaff`). | Should Workers be able to adjust stock and create products? Should the menu entry be hidden for non-admins? | TC-05, TC-30 |
| Q-10 | UI | After a successful login the app navigates to `/tasks`, which is not a defined route; the catch-all route then redirects to `/`. | Is `/tasks` a leftover? (Expected landing page for TC-01 = main menu.) | TC-01 |
| Q-11 | Realtime | `PickTasksChanged` is sent after allocation, cancel, leftover task creation and replacement tasks, but not after `POST /release` or after the 15-minute claim-timeout sweep. Other workers in the sector do not see a released task until they click "Check again". | Is this intended? | TC-28, TC-31, TC-32 |
| Q-12 | Realtime / access | `PickTaskHub` requires only authentication: the Integration role can connect and any user can join any sector group. | Is this acceptable from a security point of view? | API-19/20 |
| Q-13 | Pick task status | Code comment in `CancelPickTaskAsync` describes a known gap: a task whose lines were all written off as missing (0 picked) can be cancelled, leaving the order stuck in `Picking`. | Should this be logged as a known defect, or is a fix planned before testing? | TC-27 |
| Q-14 | API contract | `PickItemDto` and `StartPickTaskDto` contain `workerId`, but the server always takes the worker from the JWT and ignores this field. | Should the field be removed from the contract / documented as ignored? | API-42, API-46 |
| Q-15 | Supervisor override | Non-GUID or unknown badge → 401; existing user without Brigadier/Admin role → 403. The UI shows the same message for both. | Is the 401/403 distinction intentional? | TC-07 |
| Q-16 | Authentication | `AddIdentity` is used without custom options, so ASP.NET Identity default password rules apply. Login has no lockout/attempt limit configured in code. | What password policy and lockout behaviour are required? | TC-02, TC-06 |
| Q-17 | Shortages | Replacement picks for missing/defective units are only searched in a hard-coded list of zones (`mp1–mp4`, `mr1–mr4`, `mg1`, `mg2`, `mg4`). Stock in any other zone (including the test zone `mp9`) is treated as unavailable. | Is `mg3` intentionally missing? Is using a non-listed test zone acceptable for shortage tests? | TC-23 |
| Q-18 | Containers | A dispatched (loaded) tote stays `Ready` at the conveyor; per code comments only a completed putaway returns a container to `Available`. | How does an outbound tote become available again after shipping? | TC-17, EX-01 |
| Q-19 | Sector selection | The sector field accepts any text; an unknown sector simply shows "No tasks available in sector X". | Should unknown sectors be validated? | TC-17, EX-03 |
| Q-20 | Environment | `GET /api/Demo/help` is anonymous and, when `DemoSettings:Enabled` is true, returns login credentials and the supervisor badge id. | Should demo mode be disabled in the test environment so that credentials are not exposed? | Test plan – environment |
| Q-21 | Shortages / order status | After a shortage write-off the order ends **ShortShipped** (a terminal status), yet its item keeps `isPendingReplenishment: true` with `shortedQuantity` 3 (observed in `evidence/BUG-01-verify.md`). No pick task is created for the shorted units, and in code the flag is only ever set (`UnfulfillableUnitHandler.cs:103`); nothing reads or clears it. | Who picks the shorted units later, and how: a back-order, a new order, or never? Should `isPendingReplenishment` be cleared once the order is ShortShipped? | TC-23, BUG-01 |
